# Process Documentation #

## What did you build ##
I built a filtering and search feature for the menu.

## How did micro-iteration feel? ##
Working in small steps did get frustrating once I got around step five because it was just a lot of back and forth and it felt like it was taking too much time and too many tokens. 

## What did self-review catch? ##
For the input in the search bar it caught a lot of possible errors that could come like if the input was null. It also caught some possible rendering issues and made it more efficient.

## Tool impressions ##
I liked using claude on the web and how it brought up a separate section for the code it generated. Having it in a different section visually made the chat not cluttered. I could definitely see myself using this again and even using it for things outside of coding.

## Self-review patterns ##
It did catch edge cases when dealing with the dollar amounts in the beginning, but it was mostly a lot of missing error handling and catching possible issues that could come up. I did not catch any errors it missed, but I did have to ask seperatly for it to generate 
CSS so that the search bar and filtering buttons would match the page. At first I expected Claude to do that itself.

## Browser tool vs CLI comparison ##
With the browser tool I had to copy and paste my code in, create the new files, and paste the new code into the files rather than Claude doing that when using the command line where it already has access to my files. Personally, I prefer using Claude in the command line because I do not have to do all the back and forth.

## When would you use micro-iteration + self-review? ##
I think this workflow makes a lot of sense for big projects, or when you are doing something that you have never done before. In the big projects you could do the steps into bigger chunks and use the review to catch anything you might not have thought of. It can also
be super beneficial when doing something new so you can learn the process correctly.
